| [ADR-042](decisions/ADR-042-document-identity-is-the-source-not-its-extraction.md) | A document's identity is its **source bytes**, not its extracted text. | [ADR-043](decisions/ADR-043-received-content-is-preserved-verbatim.md) | **Content we received is preserved byte-for-byte; a tool that would rewrite it is excluded, not obeyed.** A whitespace hook offered to "fix" the vendored ANZSRC CC-BY Turtle — measured: **28 of 28** hits sit inside `"""` literals (`skos:definition`/`scopeNote`), so it was editing a published classification's text, and nothing parses the file anyway (no rdflib). Two tests gate any formatter: *did we author it* and *is whitespace load-bearing*. Generalised to the same bend in ingest (`strip_image_placeholders` KI-14, marker stripping KI-29, de-hyphenation RG-025): the original is never edited, normalisation is inspectable, and a genuine judgement call becomes a **user option** with an opinionated default | accepted (vendored half enforced; user-facing half is direction) |
| [ADR-044](decisions/ADR-044-update-notification-not-delivery.md) | **The app tells you a new version exists; it never installs one.** Notification only — one opt-in HTTPS GET to the public GitHub Releases API, then a link. **Three states, never two:** a failed check is `unknown`, never "up to date". Automatic checking is off by default; the manual "Check now" always runs, because an explicit press is its own consent. In-app delivery rejected for this stage (needs code signing, rollback, and a release process that has actually produced a verified artifact). First outbound network feature to ship — ADR-032 inherits its transport/privacy discipline | accepted (built) |
| [ADR-045](decisions/ADR-045-taxonomy-display-rule-and-document-identity.md) | **Show the most specific label, search the whole ancestry.** Fills the display rule ADR-028 left explicitly unspecified: a document shows its attached nodes **minus any that is an ancestor of another** (polyhierarchy shows both when neither subsumes the other), while search/filter matches the **full ancestor closure** — which is what makes a coarse facet work over a vocabulary measured at **97% singletons, before and after** four extraction fixes. Attach only at the most specific node; ancestors are derived, never stored. Both rules degrade to identity on an unplaced vocabulary, which is **today: 13 of 357 concepts placed, 0 `is_a` edges** — the machinery is built, the taxonomy is empty. A document identity key (`rag_lewis_2020`) is a **computed field, not a vocabulary row** (it is an identifier, `df=1` forever, and would manufacture the singletons this repairs); bibliographic type/origin are **metadata columns**, not taxonomy nodes, because "is a journal article" is not "belongs to a research field" | accepted (design; unbuilt) |
| [ADR-046](decisions/ADR-046-added-documents-copy-or-reference.md) | **A document you add is either copied in or referenced in place, and the app must know which.** Both modes ship in v1 (user, over a recommendation of copy-in-first) because it is the only option that does not make the Zotero adapter a second migration. Three contracts change: `SourceFile` becomes `(root, rel_path)` — it is keyed *relative to the source dir* today, so referencing a file elsewhere is a **schema** change, not a UI one; **ADR-014 is amended** — `delete_document` bins the source *first*, which would take files out of a user's own Zotero folder, so delete now asks and defaults to library-only, naming the real path when the file is referenced; and add-time identity becomes **sha256 of the source bytes**, deliberately leading ADR-042 while `doc_hash(extracted)` still answers "already indexed?" — the two coexist until RG-027 collapses them. Absorbs the queued library-only-delete item | accepted — **both placement modes built** (AD1-AD3a 2026-08-24, AD3b 2026-08-25): `SourceFile` is keyed `(root_id, rel_path)` against a new `SourceRoot`, the scan/selection/exclusion paths are multi-root, and an unreachable root reports *unavailable* rather than showing its files as mass deletion. The **amended-delete half is still design** — `delete_document` does not yet take `delete_file` |
| [ADR-047](decisions/ADR-047-document-identity-survives-re-extraction.md) | **A document's identity is its source file, not its extracted text.** `_existing_document_id` resolved on `doc_hash(extracted_text)`, so every extraction improvement minted a fresh id and cut loose everything keyed to the old one — **measured at 4,123 orphaned rows** on the live library, including 881 figure descriptions and 19 nobody can regenerate (18 folder assignments and a typed metadata override). The hash stays the first key; the **source path** is the fallback. `upsert_document_in_sqlite` moves to the resolved id with it, because a hash lookup would now miss and collide on the primary key. Partially executes ADR-042; **RG-027 stays open** — identity is path-shaped, not content-shaped, so a moved file still reads as new. The cost, asserted in tests: a different file written to the same path inherits the identity | accepted (built) |
| [ADR-048](decisions/ADR-048-per-part-re-ingest-scope.md) | **Re-ingest is per part, and only the parts one document can honestly own.** Four parts — metadata · figures · references · text — chosen from the measured record, not taste: they differ in cost by four orders of magnitude, so each states what it will spend before it runs. Keywords, connections, epistemics and gaps are corpus-global by construction (scoping keywords to one document was measured to save 4%) and are **named and declined** rather than hidden. `text` is the only part that moves `doc_hash`, and it purges the superseded chunks itself — `ingest.main` skips cleanup on the `files is not None` path, so without that the document is silently indexed twice. |
| [ADR-049](decisions/ADR-049-ingestion-adapters-and-external-metadata.md) | **An ingestion adapter returns paths, and a catalogue's metadata is a third slot.** Row 17's Zotero import stops at absolute paths and lets the *existing* review sheet do the rest — same duplicate rule, same copy-or-reference choice — so re-importing a library you already have is just an add where everything reads as a duplicate. The vendor boundary is a package split, not a promise: `adapters/catalogue.py` is neutral, `adapters/zotero.py` is the only module that knows a `linkMode`, and Calibre is one module plus one route. The half worth having is the curated metadata, which needed somewhere to live: `ExternalMetadata` sits **between** the extractor's guess and the user's own edit (ADR-013 still wins), keyed by *path* because it arrives before the document exists — and `_rerun_metadata` re-applies it rather than overwriting it with a guess. Two things found by driving it: Zotero gives every attachment its own `storage/<key>/` folder, so the per-parent root rule would mint one `SourceRoot` per document (fixed by an explicit batch root plus preferring an already-registered ancestor); and the catalogue is read from a **copy**, because Zotero holds its database open. **Not verified against a real library** — the fixture builds the documented schema, so the tests prove the mapping, not the schema | accepted (built, Zotero) |
| [ADR-050](decisions/ADR-050-source-viewer-page-rendering.md) | **The source viewer renders pages on the server, and finds its page in the cache.** Row 18's pane asks for one page at a time from `GET /api/library/documents/{id}/page/{n}` (PNG, PyMuPDF on demand — the same `get_pixmap` the figure pass uses), because `apps/` are thin shells and the app already serves binaries this way (`figureUrl`). Measured: 19-31 ms and 140-261 KB a page, so nothing is pre-rendered or cached — the whole corpus up front would be ~760 MB and ~90 s. The cost is stated rather than discovered: a page image has no selectable text or in-page find, which is accepted because row 19's extracted-text view already is that surface. **The row's own premise was wrong and is corrected here:** it claimed page-level jump is free because "chunks already carry `page`", but `USE_PARENT_CHILD` is the retrieval path and only **615 of 39,705** of its chunks (1.5%) carry one — all of them figure chunks. It is free for a different reason: the cache carries `<!-- page:N -->` on **98/98** documents (count == `page_count`, sequential) and chunks carry `parent_char_start` at 100% after row 19's re-chunk, so the page is a read-time scan the flat path already does (`chunking.extract_chunk_metadata`). PDF renders pages; every other format degrades to its extracted text and says why. The passage highlight *on the image* is scoped out — offsets are not coordinates, and read-time matching accuracy is unmeasured | accepted (2026-09-01) |
